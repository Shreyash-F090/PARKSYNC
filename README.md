# PARKSYNC

PARKSYNC is a parking-reservation and operations app for customers and facility administrators. The browser client is plain HTML, CSS, and Vanilla JavaScript; the API is Java 21 with Spring Boot 3.2.5 and Maven; persisted data is stored in MySQL 8.

## What is included

- Customer registration and login, profile and password changes, vehicle management, facility search, slot selection, fee quotes, reservations, cancellation, check-in/out history, notifications, support requests, and payment records.
- Administrator dashboard and reports, customer account controls, facility and slot management, booking search, entry/exit recording, payment records, and support replies.
- MySQL schema migrations and clearly marked sample facilities.
- Server-calculated fees. Payment options create demo records only; they do not charge money or connect to a payment processor.
- An OpenAPI contract at `lib/api-spec/openapi.yaml`.

Facilities and rates seeded by the project are demonstrations, not confirmed operator listings or live availability. Verify prices, hours, and parking conditions with an operator before relying on them.

## Requirements

- Java 21
- Maven 3.8+
- MySQL 8
- Node.js 22.13+ and npm (frontend build/dev only)

## Run locally

1. Create a MySQL database and user, or use an existing MySQL connection:

   ```sql
   CREATE DATABASE parksync CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
   CREATE USER 'parksync'@'localhost' IDENTIFIED BY 'choose-a-local-password';
   GRANT ALL PRIVILEGES ON parksync.* TO 'parksync'@'localhost';
   ```

2. Set the database, signing key, and administrator environment variables in your shell. Use a private random signing key of at least 32 bytes and a unique administrator password; do not commit these values.

   ```bash
   export DB_URL='jdbc:mysql://127.0.0.1:3306/parksync?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC'
   export DB_USER='parksync'
   export DB_PASSWORD='your-local-database-password'
   export APP_JWT_SECRET='replace-with-a-private-random-value-at-least-32-bytes'
   export ADMIN_EMAIL='admin@example.com'
   export ADMIN_PASSWORD='choose-a-unique-administrator-password'
   ```

3. Start the API. Flyway applies the schema and sample-data migrations on first start.

   ```bash
   bash backend/run-local.sh
   ```

   The API listens on `http://localhost:8080/api`; health check: `GET /api/healthz`. If no `DB_URL` or `DB_HOST` is set, the local runner starts an isolated MySQL instance in the user's data directory and creates a local `parksync` database/user. Set `DB_URL` to use an existing server instead.

4. In another terminal, start the browser app:

   ```bash
   cd artifacts/parksync
   npm install
   npm run dev
   ```

   Open the Vite URL shown in the terminal. The dev server forwards `/api` requests to `http://127.0.0.1:8080`. To use another API during development, set `API_PROXY_TARGET` before starting Vite.

5. To build and run the backend tests with Java 21:

   ```bash
   bash backend/build.sh
   ```

   To run the frontend syntax checks and production build:

   ```bash
   cd artifacts/parksync
   npm run typecheck
   npm run build
   ```

The initial administrator is created from `ADMIN_EMAIL` and `ADMIN_PASSWORD`; there is no public default administrator login. For deployments, keep credentials and database details in the hosting provider's private environment-variable settings.

## Deploy the frontend to Netlify

`netlify.toml` builds the static Vanilla JavaScript frontend. Create or connect the repository in Netlify and set the build environment variable `VITE_API_BASE_URL` to the deployed API origin ending in `/api`, for example `https://your-api-host.example/api`. The build intentionally fails if this value is missing rather than producing a site that silently sends API requests to Netlify.

Set `CORS_ALLOWED_ORIGINS` on the API to the exact public frontend origin, such as `https://your-site.netlify.app`. Do not include a trailing path. If you use a custom domain, add that origin too.

## Deploy the API to Render

`render.yaml` and `backend/Dockerfile` define the Java 21 API service. Connect the repository to Render and apply the Blueprint. Configure:

- `DB_URL`, `DB_USER`, and `DB_PASSWORD` for a reachable MySQL 8 database. Render's application service must be able to reach the database over the network; use the database host's required TLS settings in `DB_URL`.
- `ADMIN_EMAIL` and `ADMIN_PASSWORD` for the initial administrator.
- `CORS_ALLOWED_ORIGINS` for the Netlify site origin.
- `APP_JWT_SECRET` is generated by the Render Blueprint; keep it private and do not rotate it casually because active sessions use it to validate their tokens.

The Render health check is `/api/healthz`. After the API is live, set Netlify's `VITE_API_BASE_URL` to the Render API URL ending in `/api`, then redeploy the frontend.

## Tests and database behavior

The Maven test suite includes fee-rounding unit tests and an H2-backed application startup/registration test. The deployed application uses MySQL and Flyway migrations; H2 is test-only. No production database migration has been run by this project.

## Project layout

- `artifacts/parksync/` — Vanilla JavaScript frontend
- `backend/` — Spring Boot application, MySQL migrations, tests, build/run scripts, and Dockerfile
- `lib/api-spec/openapi.yaml` — API contract
- `netlify.toml` — static frontend deployment settings
- `render.yaml` — API deployment Blueprint
